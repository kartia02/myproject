# Pet Detective v1.1 구현 명세

이 문서는 `Pet Detective — 개인 반려견 행동 변화 분석 AI Agent 기획서.md`를 코드 수준으로 구체화한 현재 구현 기준이다. v1.0의 공개 합성 데모에 v1.1 브라우저 기반 개인 기록 체험을 추가했다.

현재의 필수 4-Tool 호출 구조를 질문별 동적 Tool 선택 구조로 전환하는 후속 작업은 [Agent 오케스트레이션 전환 계획](agent-orchestration-plan.md)에 기록한다.

## 확정 범위

- 사전 생성 Synthetic Scenario 선택형 공개 데모
- 계정과 로그인 없이 반려견 이름 등록
- 개인 일일 기록은 브라우저에 저장하며 파일 업로드와 기기 간 동기화는 제공하지 않음
- React + TypeScript, FastAPI, Neon PostgreSQL
- OpenAI Responses API와 `gpt-5.6-luna`를 기본 Agent 모델로 사용
- 월 API 비용 $5 이하를 목표로 요청당 최대 4회 Tool 호출, 최대 900 출력 토큰, 분당 10회 제한 적용
- API Key 또는 LLM 호출 실패 시 계산된 Evidence를 이용한 안전한 규칙 기반 리포트 제공
- P1 Timeline Search와 P2 Adaptive Baseline은 v1.0에서 제외

## 사용자 체험 모드

최초 접속 시 반려견 이름을 필수로 받고 나이와 견종은 선택적으로 받는다. 사용자는 다음 두 모드 중 하나를 선택하며 초기화 기능으로 다시 선택할 수 있다.

1. **예시 데이터로 바로 체험**: 기존 60일 합성 시나리오를 등록한 반려견 이름으로 표시한다. 이름 개인화가 합성 기록을 실제 데이터로 바꾸지는 않으며 화면에 이 사실을 명시한다.
2. **직접 기록 시작**: 날짜와 행동·환경 지표를 직접 입력한다. 같은 날짜를 다시 저장하면 기존 기록을 수정하고, 개별 삭제와 JSON 내보내기를 지원한다. 첫 기록일부터 오늘까지 비어 있는 날짜를 탐지해 최근 누락일을 표시하며, 날짜를 선택하면 지난 기록 입력 폼으로 이동한다. 미래 날짜 입력은 허용하지 않는다.

프로필과 직접 기록은 `pet-detective.workspace.v1` 키로 현재 브라우저의 `localStorage`에 저장한다. 브라우저 저장소를 지우거나 다른 기기에서 접속하면 자동으로 이어지지 않는다.

직접 기록 분석에는 서로 다른 날짜 37일이 필요하다. 날짜순 최초 30일을 Personal Baseline으로, 마지막 7일을 현재 비교 구간으로 사용한다. 37일 미만이면 남은 일수를 안내하고 Luna를 호출하지 않는다. 누락일은 사용자에게 보완 기회를 제공하지만 분석을 영구히 막지는 않는다. 이 요건은 일정한 Baseline과 비교 기간을 유지해 합성 시나리오와 같은 분석 계약을 적용하기 위한 것이다.

분석 실행 시 이름, 일별 기록, 이벤트와 질문이 요청 처리 동안 Backend와 OpenAI에 전달될 수 있다. 이 값들은 Neon에 저장하지 않는다. Neon에는 공개 데모의 일일 Agent 사용량 제한에 필요한 익명 상태·실행 모드·사용량 메타데이터만 저장한다.

## 데이터 계약

기록은 반려견·날짜별 일일 집계다. 행동 지표는 활동 시간, 수면 시간, 야간 각성, 식사량, 저녁 산책, 긁기, 짖기이며 환경 지표는 평균 기온과 강수량이다. `0`은 관측값이고 결측값과 구분한다. 합성 데이터와 개인 기록 입력에는 결측값을 넣지 않는다.

각 시나리오는 60일이며 재현 가능한 고정 seed로 생성한다.

1. `night-restlessness`: 저녁 산책 감소, 3일 뒤 야간 각성 증가, 2일 뒤 긁기 증가
2. `rainy-slowdown`: 연속 강수와 같은 시기에 저녁 산책 및 활동 감소
3. `stable-routine`: 삽입 변화가 없는 음성 대조군

Ground Truth는 `evaluation/ground_truth.json`에만 보관하며 서비스와 Agent Tool에는 제공하지 않는다.

## 분석 규칙

- Baseline: 최초 30일의 평균, 표준편차, 중앙값
- 현재 비교 구간: 데이터상 마지막 날짜까지의 7일
- 변화 후보: Baseline 평균 대비 지표별 최소 변화율, 최소 절대 변화량, 1.5 표준편차 이상의 차이를 모두 충족
- 지속 조건: 최근 7일 중 4일 이상이 Baseline 평균에서 같은 방향으로 1 표준편차를 벗어남
- 시작일: Baseline 이후 4일 창에서 3일 이상 같은 방향으로 벗어난 최초 날짜
- 결과: severity 순서로 최대 3개
- 데이터 부족과 변화 없음은 별도 상태로 구분

지표별 최소 절대 변화량은 활동 시간 10분, 수면 시간 0.5시간, 야간 각성 0.75회, 식사량 20g, 저녁 산책 7분, 긁기 1.5회, 짖기 2.5회다. 이 기준은 Baseline이 0이거나 매우 작을 때 미세한 흔들림이 큰 변화율로 계산되는 오탐을 막는다.

## Agent와 Evidence

숫자는 Python 분석 모듈에서 계산한다. Agent는 다음 Tool만 호출한다.

- `get_baseline()`
- `detect_changes()`
- `compare_periods()`
- `get_events()`

Agent 응답을 사용하려면 한 번의 조사에서 위 네 Tool을 각각 정확히 한 번 호출해야 한다. 하나라도 호출하지 않거나 같은 Tool을 반복 호출하면 Tool 검증 실패로 처리하고 안전한 규칙 기반 리포트로 대체한다. 이 조건을 포함해 한 요청의 Tool 호출 수는 최대 4회다.

변화 Evidence에는 최근 비교 구간뿐 아니라 Python 분석 엔진이 계산한 변화 시작일을 포함한다. 변화가 하나도 없으면 Luna API를 호출하지 않고 계산 기반 리포트를 반환한다. 실제 호출 시 API 요청 수, Tool 호출 수, 입력·출력 토큰, 지연 시간과 최종 채택 여부를 기록한다.

Evidence에는 고유 ID, 지표, 기준 기간, 비교 기간, 기준값, 관측값, 단위, 원본 날짜가 포함된다. 자연어 응답은 각 문장에 `[E1]` 형식으로 Evidence ID를 연결해야 한다. 존재하지 않는 ID, 근거에 없는 수치·날짜, 명시적인 인과·진단 주장이 포함되면 LLM 응답을 사용하지 않고 안전한 리포트로 대체한다.

서비스는 동시에 나타난 변화와 날짜 기반 이벤트를 설명할 수 있지만 원인 또는 질병으로 표현하지 않는다.

### 질문부터 응답까지의 실행 순서

```text
반려견 일상 데이터
    ↓
사용자 질문
    ↓
Luna가 질문을 해석하고 조사 계획 결정
    ↓
Luna가 필요한 Tool 호출
    ↓
Python·SQL이 데이터 조회 및 통계 분석
    ↓
분석 결과를 Luna에게 반환
    ↓
필요하면 Luna가 추가 Tool 호출
    ↓
Luna가 Evidence 기반 설명 작성
    ↓
서버가 Evidence ID를 검증
    ↓
사용자에게 결과 전달
```

Luna는 통계를 직접 계산하지 않는다. 사용자 질문에 맞춰 어떤 정보를 조사할지 판단하고 Tool을 선택한다. Tool 내부의 Python·SQL이 Baseline, 변화율, 변화 시작일, 기간별 비교 및 이벤트 조회를 계산한다. Luna는 Tool 결과에 포함된 사실만 사용해 보호자가 이해하기 쉬운 설명을 작성한다.

조사 요청이 시작되면 서버가 DB에서 시나리오를 한 번 읽어 조사 컨텍스트로 고정한다. 안전한 fallback과 Agent Tool은 이 동일한 데이터 스냅샷 및 Python 분석 함수를 사용한다. Tool은 모델로부터 시나리오 ID를 받지 않으므로 조사 도중 다른 시나리오로 전환할 수 없다.

### 결과와 관련 요인의 경계

Pet Detective가 도출하는 것은 확정된 원인이 아니라 관찰된 변화와 관련 요인이다.

| 구분 | 시스템이 답할 수 있는 내용 |
| --- | --- |
| 변화 | 무엇이 평소와 달라졌는가 |
| 시점 | 언제부터 변화가 나타났는가 |
| 동시 변화 | 같은 기간에 다른 지표가 어떻게 달라졌는가 |
| 관련 기록 | 변화 시점 주변에 어떤 이벤트가 기록되었는가 |

다음과 같은 인과 또는 의학적 주장은 생성하지 않는다.

- 산책 감소가 야간 각성 증가의 원인이다.
- 긁기 증가가 특정 질병 때문이다.
- 함께 발생한 두 변화 사이에 인과관계가 있다.

최종 설명은 “같은 시기에 나타났다”, “비슷한 시점부터 관찰됐다”, “현재 기록만으로 인과관계를 판단할 수 없다”와 같은 표현을 사용한다.

### 구성요소별 책임

| 구성요소 | 책임 |
| --- | --- |
| PostgreSQL | 일별 기록, 이벤트, 조사 결과 저장과 기간 조회 |
| Python 분석 엔진 | Baseline, 변화량, 지속 조건, 변화 시작일 계산 |
| Luna Agent | 질문 해석, Tool 선택, 추가 조사 판단, Evidence 기반 설명 |
| Tool | Agent와 Python·SQL 분석 기능 사이의 구조화된 계약 |
| 검증 계층 | 문장별 Evidence ID, Evidence에 존재하는 수치·날짜, 명시적 인과·진단 표현 검증 |
| React UI | 질문 입력, 변화 결과, 근거 및 조사 과정 표시 |

## 평가 규칙

변화 탐지는 지표와 방향이 모두 같은 경우 한 건의 정탐으로 계산한다. Precision, Recall, F1 및 시작일 평균 절대 오차를 보고한다. 고정 공개 시나리오와 함께 7개 행동 지표 각각의 증가·감소, 임계값 미만 변화, 단일 일자 이상치, 변화 없음으로 구성된 결정론적 강건성 케이스를 실행한다. Evidence Precision은 응답이 인용한 Evidence ID 중 실제 생성된 ID의 비율이고 Unsupported Claim Rate는 그 보수적 보수값이다. LLM 자연어의 의미 단위 평가는 API Key 설정 후 별도 표본 검토한다.
